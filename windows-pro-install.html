Thessley computer installation

Windows 11 Pro office client

One command installs OpenSSH, adds your key and applies the Office PC Users logon model.

All downloads · Windows agent · Linux · AD service

Before you start

  • Windows 11 Pro, Enterprise or Education, installed and joined to the domain (Home cannot join a domain or host RDP).
  • An elevated PowerShell window, the account signed in once, and its public key on the clipboard.
  • A local break-glass administrator you can still use if the domain is unreachable.

Guided install

Three steps in an elevated PowerShell window. The installer never installs OpenSSH: that is step 1, and it stays your call.

Step 1 — Install OpenSSH Server

Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Set-Service -Name sshd -StartupType Automatic
Start-Service sshd
New-NetFirewallRule -Name OpenSSH-Server-In-TCP -DisplayName "OpenSSH Server (sshd)" `
  -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22

Step 2 — Add the key

Copy the account’s public key first, or paste a URL that serves it (for example https://github.com/alice.keys) at the prompt.

& ([scriptblock]::Create((irm https://wp-opsec.eagleeye-intelligence.com/wp-content/uploads/thessley-downloads/windows-office-client.ps1))) -SshOnly

No key yet? The normal exchange is two commands on the computer you connect from:

ssh-keygen -t ed25519 -C "alice@laptop"
cat ~/.ssh/id_ed25519.pub      # PowerShell: Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub

Paste that line at the installer prompt, or point the installer at a file or URL with -KeyUrl.

It adds the key with Windows sshd’s ACLs, sets PubkeyAuthentication yes, turns password sign-in off and restarts sshd. Then test it from another computer: ssh -i <key> <user>@<host>.

Step 3 — The office logon model

& ([scriptblock]::Create((irm https://wp-opsec.eagleeye-intelligence.com/wp-content/uploads/thessley-downloads/windows-office-client.ps1))) -LogonModelOnly

Creates the local group Office PC Users and allows only Administrators and that group to sign in locally, over Remote Desktop and over the network. Keep the console open while you do it.

Both installer steps at once, after step 1: irm https://wp-opsec.eagleeye-intelligence.com/wp-content/uploads/thessley-downloads/windows-office-client.ps1 | iex

Options: -User 'CONTOSO\alice' · -KeyUrl https://github.com/alice.keys · -KeepPasswordAuth · -Group 'Office PC Users' · -Rollback.

Anything replaced is copied to C:\ProgramData\ThessleyOffice\backup-<timestamp> first. The SHA-256 checksums cover the installer if you want to verify it first.

Manual setup, command by command

Install OpenSSH Server

Windows ships OpenSSH as a capability. Install the server, start it at boot, and open only TCP 22.

Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Set-Service -Name sshd -StartupType Automatic
Start-Service sshd
New-NetFirewallRule -Name OpenSSH-Server-In-TCP -DisplayName "OpenSSH Server (sshd)" `
  -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22

Add the public key

For a standard (non-administrator) account the key goes in that user’s own profile. Run this as that user after their first sign-in:

$key = 'ssh-ed25519 AAAA... your-name@your-host'
$dir = Join-Path $env:USERPROFILE '.ssh'
New-Item -ItemType Directory -Force $dir | Out-Null
Add-Content -Path (Join-Path $dir 'authorized_keys') -Value $key
icacls $dir /inheritance:r /grant "$($env:USERNAME):(OI)(CI)F" /grant "SYSTEM:(OI)(CI)F"
icacls (Join-Path $dir 'authorized_keys') /inheritance:r /grant "$($env:USERNAME):F" /grant "SYSTEM:F"

The default C:\ProgramData\ssh\sshd_config ends with a Match Group administrators block that redirects administrator keys to a shared file. Either leave it and put the key in C:\ProgramData\ssh\administrators_authorized_keys (ACL: Administrators and SYSTEM only), or remove that block if every account uses its own profile:

icacls C:\ProgramData\ssh\administrators_authorized_keys /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"

Turn off password sign-in

PubkeyAuthentication yes
PasswordAuthentication no

Put those two lines in C:\ProgramData\ssh\sshd_config, then restart and test from another computer:

Restart-Service sshd
ssh -i ~/.ssh/<key> <user>@<host>

The office logon model

The goal: only administrators and members of a local Office PC Users group may sign in at the PC, over Remote Desktop, and over the network. Everything else is refused, including SSH.

New-LocalGroup -Name "Office PC Users" -Description "May sign in at this PC"
Add-LocalGroupMember -Group "Office PC Users" -Member "CONTOSO\alice"

Keep a way back in. Before changing logon rights, export the current policy and keep a local administrator plus console access. If the only account allowed to sign in is a domain account and the domain is unreachable, the PC is locked out.

secedit /export /cfg C:\Windows\Temp\secpol-before.inf

Create C:\Windows\Temp\office-rights.inf with these rights. *S-1-5-32-544 is the local Administrators group; the group name is the local group created above.

[Unicode]
Unicode=yes
[Version]
signature="$CHICAGO$"
Revision=1
[Privilege Rights]
SeInteractiveLogonRight = *S-1-5-32-544,Office PC Users
SeRemoteInteractiveLogonRight = *S-1-5-32-544,Office PC Users
SeNetworkLogonRight = *S-1-5-32-544,Office PC Users
secedit /configure /db C:\Windows\Temp\secedit.sdb /cfg C:\Windows\Temp\office-rights.inf /areas USER_RIGHTS
gpupdate /force

Do not leave out SeNetworkLogonRight. SSH signs in as a network logon. With only the interactive and Remote Desktop rights, a correct key is still answered with Permission denied (publickey) — the exact failure this lab hit. The safe set is all three rights for the same two principals.

Roll back

secedit /configure /db C:\Windows\Temp\secedit.sdb /cfg C:\Windows\Temp\secpol-before.inf /areas USER_RIGHTS

Verify

  • Sign in at the console and over RDP as the account: both work, and it is an ordinary user.
  • ssh -i <key> <user>@<host> opens a shell.
  • An account in neither Administrators nor Office PC Users is refused by all three.

If it goes wrong

  • Passkey tile says “Approval failed or expired” — the AD service is not reachable: check sc.exe query ThessleyADApi on the domain controller. “1060” means it is not installed (see the AD service guide).
  • “Permission denied (publickey)” with a good key — profile key vs administrators_authorized_keys, file ACLs, or SeNetworkLogonRight.
  • Domain trust failed — sign in locally and run Reset-ComputerMachinePassword -Server DC1 -Credential (Get-Credential CONTOSO\Administrator), then reboot.
  • SSH slow right after boot — wait for the domain controller and retry.
