Step 1: install and verify Windows OpenSSH

Do this separately before installing Thessley. On the Windows PC, open PowerShell as Administrator and install the built-in OpenSSH Server feature. This setup only enables SSH and its firewall rule; it does not install or configure Thessley.

$ErrorActionPreference = 'Stop'
$cap = Get-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
if ($cap.State -ne 'Installed') { Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0 | Out-Null }
$service = Get-Service -Name sshd -ErrorAction SilentlyContinue
if (-not $service) { throw 'OpenSSH Server capability is installed but sshd is missing. Follow the repair steps below before continuing.' }
Set-Service sshd -StartupType Automatic
Start-Service sshd
Get-Service sshd
if (Get-NetFirewallRule -Name OpenSSH-Server-In-TCP -ErrorAction SilentlyContinue) {
    Set-NetFirewallRule -Name OpenSSH-Server-In-TCP -Enabled True -RemoteAddress LocalSubnet
} else {
    New-NetFirewallRule -Name 'OpenSSH-Server-In-TCP' -DisplayName 'OpenSSH Server (sshd)' -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22 -RemoteAddress LocalSubnet
}

If the command says the capability is installed but sshd is missing, repair the Windows optional feature first. Back up C:\ProgramData\ssh if it exists, remove only the OpenSSH Server capability, restart Windows, then rerun the setup command above:

Remove-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Restart-Computer

The command scopes SSH to the local subnet, including when Windows classifies the network as Public. To allow a VPN client subnet too, add that exact subnet to -RemoteAddress. For a cloud VM, this LAN-only rule will not accept remote SSH: allow TCP 22 in the provider security group and open the VM firewall from your intended admin sources before connecting. The guided Thessley installer can add a separate cloud firewall rule for TCP 22. From another computer, verify the IP and connect with ssh WINDOWS_USER@WINDOWS_IP. Approve the host key and confirm you reach a Windows prompt.

Only after that SSH check succeeds, install Thessley below. For remote installation, connect as an administrator and check that the SSH session has an administrator token. If it returns False, use the Windows console for the install; do not weaken UAC or broaden the firewall to work around it.

ssh -t WINDOWS_ADMIN@WINDOWS_IP powershell.exe -NoProfile
([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)

Continue only if the check prints True, then run:

Step 2: install the Thessley service

After Step 1 confirms OpenSSH is reachable, install Thessley from Administrator PowerShell on the PC, or from a verified administrator SSH session. The bootstrap verifies the service package checksum. The wizard can install the approval service, optional web GUI, and firewall rules. If the administrator has no phone enrolled, it prints a separate FIRST-PHONE ENROLLMENT LINK in the form https://WINDOWS-IP:47820/TOKEN, followed by an eight-digit one-time code. Copy that complete labeled link, open it in a browser, enter the code, and enroll the phone. The ordinary Admin page address is not the enrollment link. The setup expires after ten minutes. The experimental Windows QR sign-in tile is also optional and has a separate rollback. SSH account policies are managed from the Admin page after installation.

irm https://wp-opsec.eagleeye-intelligence.com/wp-content/uploads/thessley-windows-downloads/install.ps1 | iex

The guided installer enables QR approval for current local SSH accounts by default and preserves their existing OpenSSH key/password settings. Until an account enrolls a phone, the configured fallback lets its normal SSH method work; once a phone is enrolled, QR approval is required. On a cloud host, answer Yes to cloud access. The wizard can allow TCP 22 and phone approvals on TCP 47810 from changing public IPs; remote access to the web page on TCP 47820 is a separate opt-in. Add the same required ingress ports in the cloud provider's security group, which this installer cannot manage. On the Windows Admin page, open Users to set QR approval and block SSH separately for each account. Leave your current SSH session open, then test a new SSH login for every changed account. If you chose the Windows sign-in tile, test it at the Windows sign-in screen too. Only after the sign-in tile works, run elevated:

powershell -ExecutionPolicy Bypass -File "$env:ProgramData\ThessleyPamWin\confirm-setup.ps1"

Each Admin-page SSH change backs up C:\ProgramData\ssh\sshd_config under C:\ProgramData\ThessleyPamWin\backups, validates it, then restarts OpenSSH. If a test login fails, use the Admin page to turn QR off for that account or restore the shown backup from an elevated PowerShell session. The sign-in tile has its own automatic rollback timer.

Install Windows QR sign-in over SSH

First install and test the Thessley Windows service. Enroll the phone for the Windows account from an elevated PowerShell session if needed, compare the pairing codes, and verify phone approval works. Allow TCP 47810 only from the trusted LAN/VPN client subnet for phone approval and enrollment. From a trusted computer, connect to Windows with an interactive administrator PowerShell session. Continue only if the token check prints True:

ssh -t WINDOWS_ADMIN@WINDOWS_IP powershell.exe -NoProfile
([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)

In that session, download and verify the experimental package against the published checksum, then extract it:

$zip = Join-Path $env:TEMP 'windows-qr-signin-experimental.zip'
$sums = Join-Path $env:TEMP 'thessley-windows-SHA256SUMS.txt'
Invoke-WebRequest 'https://wp-opsec.eagleeye-intelligence.com/wp-content/uploads/thessley-windows-downloads/windows-qr-signin-experimental.zip' -OutFile $zip
Invoke-WebRequest 'https://wp-opsec.eagleeye-intelligence.com/wp-content/uploads/thessley-windows-downloads/SHA256SUMS.txt' -OutFile $sums
$expected = ((Get-Content $sums | Where-Object { $_ -match 'windows-qr-signin-experimental\.zip$' }) -split '\s+')[0]
if (-not $expected -or (Get-FileHash $zip -Algorithm SHA256).Hash.ToLowerInvariant() -ne $expected.ToLowerInvariant()) { throw 'Checksum mismatch; stop without installing.' }
$package = Join-Path $env:TEMP 'Thessley-QR-Windows-SignIn-Experimental'
Expand-Archive -LiteralPath $zip -DestinationPath $package -Force
Set-Location (Join-Path $package 'Thessley-QR-Windows-SignIn-Experimental\windows-logon-provider')

The guided installer can install the sign-in tile automatically. For manual installation, run install-with-rollback.ps1 -RollbackMinutes 30 the first time or update-with-rollback.ps1 -RollbackMinutes 30 for an existing provider. Keep the SSH session open and the regular Windows PIN/password tiles available. The QR viewer executable only renders the QR window; the credential provider DLL registers the actual tile.

Use the Windows console or Remote Desktop to complete setup at the Windows sign-in screen: choose the Thessley tile, select Set up QR-only sign-in, approve on the enrolled phone, enter the current Windows password once, and sign in. Test a second QR sign-in. If anything fails, use the built-in PIN/password tile or let automatic rollback run. After QR sign-in succeeds, confirm from the still-open elevated SSH session:

powershell -ExecutionPolicy Bypass -File "$env:ProgramData\ThessleyPamWin\confirm-setup.ps1"

This provider is experimental and the QR sign-in screen itself requires interactive access; SSH is used to stage and install it. Phone enrollment and approval use the normal network connection. No ADB, USB debugging, or phone cable is used.

Manual Windows SSH + Web GUI installation

  1. Complete Step 1 above first. Confirm sshd is running and a normal SSH login works from the LAN before configuring Thessley.

For OpenSSH details, see Microsoft’s OpenSSH Server installation guide.

  1. Install Python 3.10 or later for all users. For example, in administrator PowerShell:
winget install --id Python.Python.3.13 --scope machine
  1. Download and extract windows-ssh-webgui.zip, for example to C:\Thessley\Windows-SSH-WebGUI.
  2. In administrator PowerShell, run the installer. Adjust the Python path if your installed version differs:

Adjust the folder if you extracted the package somewhere else. The installer is under the install subfolder:

Set-Location C:\Thessley\Windows-SSH-WebGUI
powershell -ExecutionPolicy Bypass -File .\install\install.ps1 `
  -Python "C:\Program Files\Python313\python.exe" `
  -OpenFirewall -OpenWebFirewall

The optional firewall switches allow phone approvals and enrollment on TCP 47810 and the web page on TCP 47820 from the local subnet on all Windows network profiles. Enrollment requests share the service-owned 47810 listener, including concurrent requests. When asked about VPN access, answer Y (or press Enter) to allow both 10.8.0.0/24 and 10.8.1.0/24, N to skip VPN access, or enter custom comma-separated IPv4 CIDR ranges. For cloud hosts, use the guided installer's cloud option instead of VPN subnets: it can allow TCP 22, 47810, and optionally 47820 from any remote IP. Cloud provider ingress rules are separate. The installer does not edit sshd_config or restart OpenSSH.

  1. Run ThessleySignInTest.exe from the desktop approval helper, choose Enroll this account, and compare the pairing codes shown by the computer and phone before confirming.
  2. Turn on the web page and check its certificate fingerprint:
& "C:\ProgramData\ThessleyPamWin\thessley-pam-win.cmd" web on

Open https://<Windows-computer-IP>:47820/ from the local network. Approve the sign-in on the phone and compare the browser certificate fingerprint with web status.

Enable QR approval for SSH

The guided installer enables QR approval for current local accounts by default. Until each account enrolls a phone, its existing OpenSSH key/password settings continue to work; enrollment turns on QR approval for that account. Open Admin → Users to change an account's QR requirement or block SSH entirely. Every change needs a fresh approval from an admin phone. The page backs up and validates C:\ProgramData\ssh\sshd_config before restarting OpenSSH. Keep an existing SSH session open and test a new login. Domain accounts and existing custom Match User rules are not managed by this page.

For manual configuration only, keep an administrator SSH session open and generate an account-specific block, choosing the first factor you want:

& "C:\ProgramData\ThessleyPamWin\thessley-pam-win.cmd" sshd-config --user YOURNAME --factor password
  • --factor password: Windows account password, then phone approval.
  • --factor key: SSH key, then phone approval.
  • --factor key-password: SSH key and account password, then phone approval.

Add the generated Match User block above the stock Match Group administrators block. Back up the configuration, validate it before restarting OpenSSH, and test a second session:

& "C:\Program Files\OpenSSH\sshd.exe" -t
Restart-Service sshd

Test from a second computer while keeping the original session open. If validation fails, do not restart the service.

Remove the Windows service

First remove the Thessley block from sshd_config, validate the file, and restart OpenSSH. Then run the uninstaller as administrator. It refuses to remove the gate while OpenSSH still references it.

& "C:\Program Files\OpenSSH\sshd.exe" -t
Restart-Service sshd
Set-Location C:\Thessley\Windows-SSH-WebGUI
powershell -ExecutionPolicy Bypass -File .\install\uninstall.ps1
